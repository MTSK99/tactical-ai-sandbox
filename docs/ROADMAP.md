### P1-1 的两个关键设计决定（详见 ADR-007）

1. **不能用"射线相交"**。它与「候选点必须通视目标」这条硬约束自相矛盾——
   一旦要求通视，连线上按定义就没有阻挡格，掩护度得分会恒为 0（实测 121/121 全灭）。
2. **判据要放进 AI 层**。第一版把它写成 `Enemy.cpp` 里的 lambda，
   结果**无法单测**，只能靠跑无头模拟间接观察。移到
   `EQS::coverEffectivenessTest` 后才有 11 条精确测试。

验证方式不止于"测试变绿"：每个修复都把代码临时改回修复前的样子，
确认对应测试**确实会失败**，再恢复。
- `coverEffectivenessTest`：还原成旧的距离代理后，**3 条测试失败**
  （`ScoresHigherWhenCoverIsOnFiringLine` /
  `DistinguishesCoverPositionNotJustDistance` / `PicksBestCoverAmongMultiple`）
- 搜索行为那条前后改了四版测试才做对（见 `test_enemy_search.cpp` 注释记录的三次假绿）

### 修复过程中发现的额外问题

1. **我的修复一度引入了回归**：`worldToGrid` 会把越界坐标钳制到边界格，
   原来的 3x3 循环靠 `inBounds(probe)` 顺手拦掉了越界点；
   改成"只看中心格"的快路径后越界判断消失，`x=-10` 被判成可站立。
   写测试时才发现，已显式补回 `navGrid_.contains()`。
   **教训：把一处逻辑"简化"掉时，要确认它顺带承担了哪些别的职责。**

2. **填矩形墙在网格上占两列**：`fillRect` 按格子填，边界没对齐格心时
   "厚 32 的墙"会封住第 24、25 两列。测试常量是实测出来的，不是推导出来的。

3. **`updateAI` 不做位置积分**：它只算速度，积分在 `Entity::update()` 里，
   由 `World::update()` 调用。绕过 World 直接调 `updateAI` 的话，
   敌人"想走"但"没走"，测出来的位移恒为 0。

## 一、结论先说

这个项目**不是一个"没做完的 demo"，而是一个内核质量很高、外壳明显空缺的实验台**。

AI 层（BT / Blackboard / Perception / EQS / Pathfinding）已达到可用于生产讨论的水平：
语义完整、注释解释「为什么」而不只是「是什么」、确定性被当作硬约束。
代码里遍布 `【修复】` 标记，记录了信息泄露、集体发呆、非确定性路径等**真实跑出来的 bug**。

真正的缺口只有两类：

| 类别 | 表现 |
|---|---|
| **闭环缺失** | 打完没有任何结果 —— 玩家死了不结束，敌人清了不结束 ✅ **已修** |
| **可验证性缺失** | 项目最核心的三个卖点（Enemy 决策 / Perception 感知 / World 管理）**零单元测试** |

再往下是**战术深度不足**（无队伍协同、掩护度已修但仍是距离近似）——
这是"沙盒变游戏"的锦上添花，不是当前最该动的。

> 下文「二、必须先修的 P0」保留原样作为**问题溯源记录**，
> 修复细节见上面的第零节。

## 二、必须先修的 P0（有实测证据）

### P0-1 玩家死亡 → 世界死机（最严重）

**证据**（已实跑确认）：

```cpp
// World.cpp:707  collectPerceptionTargets()
if (target.alive) {
    perceptionTargets_.push_back(target);   // ← 玩家一死，这里就空了
}
```

玩家死亡 → `perceptionTargets_` 清空 → 敌人失去感知目标 → 行为树回落到
`Patrol` 分支 → **不再开火、世界上再无子弹**。

09-29 日志记录的实锤：30 秒与 60 秒两次无头运行统计**完全相同**
（shots=20 / dmg=100 / kills=0 / enemies 4/4）。模拟彻底停摆，
连"观察失败现场"都做不到。

**更深一层**：全项目 `grep` 无任何胜负判定。`World.h:334` 有一个
`lastPlayerDeathCount_` 字段，声明了但**全项目从未被读写** —— 这是
"玩家死亡处理"没做完留下的残骸。

**建议**：新增 `GameSession`（或 `World::outcome()`），最小闭环三态
`Running / Victory / Defeat`，并在 `main.cpp` 消费：
- 胜利/失败全屏结算
- `R` 重开（`World::reset()` 已存在且有一整段修复注释，是现成的）
- 失败时冻结输入、保留世界继续模拟（供观察尸体与弹道）

### P0-2 `isPositionWalkable` 的 3×3 膨胀检查是无效代码

**证据**（`World.cpp:527-540`）：

```cpp
if (!navGrid_.isWalkable(probe)) {
    // 允许一个格子被阻挡（贴着掩体站立是合法的）
    continue;                 // ← 不可通行时：continue
}                            // ← 可通行时：也落到循环末尾
```

两个分支执行结果**完全相同**，这个函数目前**等价于「中心格可通行」**。
注释承诺的"半径范围内格子也要可通行，否则实体会卡在墙角"从未生效。

**建议**：要么实现意图（改为统计邻域阻挡数 > N 时才拒绝），
要么删掉循环并在注释里明说「当前不做膨胀」——
**留着这段注释比留着这段假逻辑更危险**，后来者会以为它生效了。

---

### P0-3 `SearchLastKnown` 的 `arrived` 判断完全无效

**证据**（`Enemy.cpp:612-617`）：

```cpp
const bool arrived = followPath(context.fixedDelta, moveTarget_);
if (arrived) {
    // 到了却没发现敌人：原地等一会儿再放弃
    return NodeStatus::Running;
}
return NodeStatus::Running;      // ← 两个分支返回值相同
```

"放弃"从未发生。AI 到了最后已知位置后会**永久停在那里**，
直到 `searchDuration`（8s）超时切到巡逻分支。

**建议**：这是真 bug 而非设计选择——注释承诺的战术行为（到位后短暂观察
再放弃）没做。补一个 `searchArrivedAt_` 时间戳 + 观察期计时即可。

## 三、测试盲区（P0 级，因为项目卖的就是可验证性）

217 个用例里 **153 个（70%）测 AI 层**，`game/` 层只测了 Projectile /
DodgeRoll / CombatCooldown 三块。以下**零覆盖**：

### 盲区 1：`Enemy` 本身零单元测试 ← 最致命

`grep "AIState" tests/` → **零命中**。没有 `test_enemy.cpp`。

未验证的东西包括：
- **4 条行为分支**（撤退 / 交战 / 搜索 / 巡逻）各自的触发条件
- **状态机迁移**（Patrolling→Engaging→Repositioning→Retreating→Dead）从未被断言
- `useEQS=false` 退化路径（`Enemy.cpp:433-446`）从未跑过
- `predictedAimPoint` 提前量数学（目标跳变 >120 清零、指数平滑、限幅 420）
- `lateralAimError` 叉积公式
- **5 个节流常量**（`repositionInterval` / `searchDuration` / 撤退 1.5s /
  重寻路 0.5s / `kRetargetInterval=1.0`）没有一个被验证真的生效

这是项目的**核心卖点模块**，却是唯一没有直接测试的游戏逻辑。

### 盲区 2：`PerceptionSystem` 零测试

15 个查询方法 + 全部静态几何工具，**一个都没测**。其中包括
「AI 反应延迟 250ms」这个**最能体现战术 AI 真实感的卖点的唯一实现**
—— README 里专门讲了这个卖点，却没有任何断言钉住它。

盲的还有：视野锥角度、贴半径背后察觉、记忆 6s 过期、威胁等级衰减曲线。

### 盲区 3：`World` 实体管理零测试

`reset()` / `removeEntity()` / `cleanupDeadEntities()` 全无回归测试。
而这三个方法**每一段修复注释都在详细记录曾经的 bug**：
- `reset()` 的掩体列表翻倍（`World.cpp:98-100`）
- `removeEntity()` 的 use-after-free（`World.cpp:404-408`）
- `cleanupDeadEntities()` 的迭代器失效（`World.cpp:467-484`）

**代码里注释里的「【修复】」标记，本身就是一份现成的回归测试需求清单。**

## 四、战术深度（P1，沙盒变游戏的方向）

按「对战术感的贡献 / 实现成本」排序：

### P1-1 掩护度是假的（成本最低，收益最高） — ✅ 已修

> **本节保留原样作为问题溯源。** 实际实现与踩坑见第零节与 ADR-007。

原`CoverProximity` 测试项（`Enemy.cpp:208-227`）**没有做任何射线检测**，
只算候选点到最近掩体中心的欧氏距离。代码注释自己承认了两次
（`:206-207`、`:213-214`，而且是同一个函数里说了两遍）。

后果：AI 会选一个「紧贴掩体」的点，但**从不验证那个掩体是否真在它与目标之间**。
这是 EQS 四个测试项里唯一一个名不副实的（占权重 0.20）。

**原建议**：改成从候选点向目标做 LoS 射线，看是否被该掩体遮挡。

**实际做法的修正**：上面这条建议**行不通**，实测证明它是错的。
因为同时还要加一条「候选点必须能通视目标」的硬约束（否则 AI 躲进掩体后
再也开不了枪，见 `Enemy.cpp` 的 AimAndFire LoS 检查），
而一旦要求通视，「我→目标」连线上按定义就没有阻挡格——
于是「掩体与射线相交」永远为假，实测**121 个候选里掩护度得分全为 0**。

最终改用「掩体到**我→目标连线**的距离」，详见 ADR-007。

### P1-2 敌人互相穿模 — 🚫 建议撤销

`grep separation/avoid/repulsion/neighbor` in `src/game/` → **零命中**。
运行时无任何避让，多个敌人会重叠、叠在同一点上。
`findFreeSpawnPosition` 的拒绝采样只管**生成期**，管不了运行时。

> **实测推翻了这条建议。** 40秒 / 6 敌人的统计：
>
> | 场景 | 重叠占比 | 两两最小间距 |
> |---|---|---|
> | **玩家存活期间** | **0.0%** | 60.6（半径和才 22） |
> | 含死后阶段 | 32% | 0.4 |
>
> 那 32% 全部来自玩家死亡后——敌人失去感知目标，一窝蜂涌向尸体叠在一起。
> **战斗期间根本不存在这个问题**，至少 6 个敌人时没有。
> 这套 separation 现在做是浪费，除非先做难度分级并把敌人数量提上去。

**建议**：`ai/` 层加一个轻量 steering/separation 模块（空间哈希 + 半径斥力），
比上 RVO/ORCA 便宜两个数量级，足够解决视觉穿模。

### P1-3 EQS 无时间维度 → AI 微幅抖动

`EQS.h:148` 类注释自述「单次查询是无状态的」。缺的是：
- 记忆上帧最优点 + 距离阈值 + 时间滞回（hysteresis）
- 现有的只是「同分稳定排序」（`EQS.cpp:333-342`）——
  解决**同分歧义**，不解决**分数接近时的抖动**。
- 而 `gridGenerator` 的抖动种子还随 `gameTime` 变化（`EQS.cpp:74`），
  意味着**相邻两帧候选点集合本身就不一样**，分数相近的候选会交替胜出。

**建议**：`EQSResult` 加 `previousBest` + 滞回阈值。改动小，体感明显。

### P1-4 队伍协同（工作量最大，收益也最大）

现在每个敌人持有**独立的** BT / Blackboard / Perception，**零协同**：
没有包抄、没有火力掩护、没有角色分工。

`World.cpp:712-713` 的注释已经指出了入口：
> 若要让敌人之间互相感知（友军伤害、阵型保持），在此追加即可。

而 `Perception` 层连表达听觉事件的能力都没有——
`update()` 只有 `targets` 一个入参，**没有事件流**，
所以「听到枪声」这件事目前在物理上无法表达。

**建议**（按依赖顺序，不要跳步）：
1. 给 `Perception::update()` 加事件入参 + 听觉参数
2. `NavGrid::kCover` 接上访问器，掩体从黑板坐标列表改为网格标记
3. 黑板分两层（`team.*` / `self.*`）——README 已列此方向
4. 角色分工（突击 / 火力掩护 / 守卫）作为 EQS 权重差异，而非新 BT 节点

### P1-5 难度分级

`Enemy.h:50` 注释写着「所有可调参数集中一处，**便于做 AI 难度档位**」，
`Perception.h:46` 同样措辞——**两处都是「为将来准备」，当前无任何代码读取它做分级**。

所有敌人共享同一份 `EnemyConfig`（`World.cpp:331-332`），
唯一差异化是全局 `useEQS`（来自 `--no-eqs`）。

`WorldConfig::enemyProjectile` 的注释说「damage 会被每个敌人自己的
`EnemyConfig::damage` 覆盖」（`World.h:57-58`）——但由于所有敌人的
damage 都是同一个默认值 5.0，**这套覆盖机制目前没有任何实际效果**。

**好消息**：分级所需的配置已经全部集中好了，这是纯粹的接线工作。

## 六、建议的推进顺序

```
第 1 周：把地基补上（不补后面都白干）
  ├─ P0-1 胜负闭环 + 重开        ← ✅ 已完成
  ├─ P0-2 膨胀检查无效逻辑       ← ✅ 已完成
  └─ P0-3 SearchLastKnown arrived ← ✅ 已完成

第 2-3 周：给核心卖点上保险
  ├─ test_enemy.cpp      （状态机 + 4 分支 + 节流常量 + 提前量）
  ├─ test_perception.cpp （反应延迟 / 视野锥 / 记忆过期）← 优先级最高
  └─ test_world.cpp      （reset / removeEntity / cleanupDead）
     → 把代码里所有「【修复】」注释逐条转成回归测试
     注：test_enemy.cpp 已从零开始（test_enemy_search.cpp 是第一个文件），
         其余分支/状态机/提前量仍未覆盖

第 4 周：战术感（性价比排序）
  ├─ P1-1 真掩护度射线检测      ← 最高性价比
  ├─ P1-3 EQS 滞回防抖         ← 改动最小体感明显
  └─ P1-2 轻量 separation      ← 解决穿模

第 5 周+ ：从沙盒走向游戏（可选，看项目定位）
  ├─ P1-5 难度分级（接线即可）
  ├─ 队伍协同（4 步，见 P1-4，勿跳步）
  └─ 关卡程序生成 / 序列化（nlohmann-json 已链接但游戏层零使用）
```

### 优先级的一句话总结

> **先让它有结局，再给它上保险，然后用它做战术。**
>
> 现在最不该做的是加新功能——内核已经够强，
> 缺的是「能结束」和「能证明自己没坏」。

## 七、写测试时踩过的坑（留给下一个人）

这一节不是理论，是本次三个 P0 修复过程中**真实浪费掉的时间**。

### 1. 绿色的测试可能什么也没测

搜索行为的回归测试前后改了**四版**才真正有效。前三版都是绿的，
但把修复代码改回去之后它照样绿——等于没测。
最后改成"轨迹上离最后已知位置的最远距离"才稳定：
修复前 59.9 单位，修复后 332 单位，阈值取 100 两边都分得开。

**教训：写完测试必须验证它能失败。** 做法就是临时把修复改回去跑一遍。

### 2. 测量窗口必须对齐被测的那段行为

第一版测"消失后 8 秒总位移"，可那 8 秒大部分时间 AI 在**走过去**——
"能走过去"修复前后都成立，差异只在**到位之后**。

**教训：位移类断言要明确"从哪一刻开始量"。** 测量窗口没对齐，
测的就是另一段行为。（这条与 09-29 记录的翻滚测试假失败是同一类。）

### 3. 别假设 AI 的朝向

"重获目标"测试里把玩家放在敌人 `+x` 侧 120 单位——结果敌人朝 `(-0.99, 0.12)`，
玩家正好落在背后 180°，而视野是 ±45° 的锥，压根看不见。
现象是"AI 仍在巡逻"，看起来像修复没生效。

**教训：涉及感知的测试，目标位置要按 AI 的真实朝向来摆。**

### 4. 断言"看不见"要用对信号

丢失视线后 `hasConfirmedTarget()` 在 `memoryDuration` 内**仍为真**
（那正是记忆的定义）。拿它当"是否进入搜索分支"的判据会永远失败。
该用 `threatLevel()`，或直接断言记忆已过期。

### 5. 有前置条件就写成前置断言

与其在主断言失败时猜"是逻辑坏了还是前提没成立"，
不如先 `ASSERT` 掉前提。第一版三个测试都栽在这。

### 6. 别绕过 World 直接调 `Enemy::updateAI`

它只算速度，位置积分在 `Entity::update()` 里，由 `World::update()` 调用。
绕过 World 就等于"想走但没走"，位移恒为 0。

### 7. 简写代码时确认没丢掉顺带承担的职责

我把 3x3 循环换成"只看中心格"时，顺手丢掉了越界检查
（`worldToGrid` 会钳制到边界格，越界点因此被误判为可站立）。
是写测试时才撞出来的。

### 8. 地形常量要实测，不要推导

"厚 32 的墙"在 32 单位的网格上占**两列**，因为 `fillRect` 按格子填、
边界不对齐格心。测试里按"占一列"写断言，全错。
